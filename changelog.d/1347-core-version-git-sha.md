### feat(studio): GET /api/modules says which vivijure-core and which build serve the studio

`GET /api/modules` now always carries `core_version` and `git_sha` beside `studio_release`. `core_version` is the vivijure-core this worker was built with. The bundler reads it from the installed package's `package.json` at build time, so it cannot drift from what runs. `git_sha` is `env.STUDIO_GIT_SHA` as the deploy stamps it. When nothing stamps one it is `null`, which is now present instead of omitted, and never guessed. No deploy path stamps `STUDIO_GIT_SHA` yet: `wrangler.toml.example` and the studio-release render carry no such var, so it reads `null` until the deploy kit adds one. The route is unauthenticated, so both values are checked for shape before they are projected. A `git_sha` that is not 7 to 40 hex characters, or a `core_version` that is not a version, is `null`, never echoed (cf#1347).
